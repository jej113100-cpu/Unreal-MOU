# 자체 UDP relay 실행 안내

이 구현은 Steam/EOS를 대체하는 학습용 경로다. 로비/방 상태는 기존 `Server.exe`가
관리하고, 실제 게임 권한과 RPC는 계속 Unreal 리슨서버에 있다. 평상시에는 기존의
직접 연결과 UDP 홀펀칭을 먼저 시도한다. 그 경로가 실패했을 때만 게임 UDP 패킷을
서버의 relay 포트 쌍으로 투명하게 전달한다.

## 서버 실행

서버 PC의 LAN IP가 `192.168.35.75`이고 제어 서버의 외부 IPv4가 `<공인_IP>`라면:

```powershell
.\Server.exe 9000 --public-ip <공인_IP> --relay --relay-lan-ip 192.168.35.75 --relay-ports 10000-10127
```

`--public-ip`는 기존 방장 주소/홀펀칭에 쓰이고, relay도 기본적으로 같은 주소를
쓴다. relay만 다른 공인 IP를 써야 한다면 `--relay-public-ip <공인_IP>`를 추가한다.
현재 wire 형식은 IPv4 주소만 지원한다.

공유기에는 다음을 **UDP**로 서버 PC에 포워딩한다.

| 외부 포트 | 내부 대상 | 용도 |
| --- | --- | --- |
| `9000` | `192.168.35.75:9000` | 로비 제어 + 홀펀칭 엔드포인트 등록 |
| `10000-10127` | 같은 번호 범위 | relay (참여자 한 명당 포트 2개) |

기존 게임 포트 `7777`, `7778`의 BOTH 포워딩은 직접 연결을 위해 그대로 유지한다.
relay 범위는 TCP 포워딩이 필요 없다. 방화벽에서도 `Server.exe`의 해당 UDP 인바운드를
허용해야 한다.

기본 범위는 64개 포트 쌍이지만, Windows `select()`의 보수적인 제한 때문에 동시 relay
경로는 기본 24개까지다. 한 게임 참여자당 경로 하나이므로 동시에 relay를 쓰는 참여자는
최대 24명이다.

## 동작 순서

1. 방 시작 시 서버가 참여자마다 host-facing/guest-facing UDP 포트와 서로 다른 32바이트 토큰을 만든다.
2. 방장은 자기의 실제 UE listen 소켓에서 각 host 포트에 등록한다.
3. 참여자는 `RoomHostReady`를 받은 뒤 직접 후보를 먼저 시도한다.
4. 직접 후보가 모두 실패하면 참여자의 실제 UE client 소켓이 자기 guest 포트에 등록하고 그 포트로 접속한다.
5. 양쪽 등록 후 relay는 패킷 내용을 해석하지 않고 반대편에 전달한다.

`--relay-lan-ip`는 제어 서버와 같은 LAN에 있는 플레이어에게 사설 relay 주소를 내려
WAN hairpin을 피한다. 질문의 Player1(서버와 같은 LAN) / Player2(외부 LAN) 조합에서
중요하다.

## 확인 방법

- 서로 다른 NAT의 Player2를 호스트로 하고, Player1이 참가한다.
- 먼저 직접 연결이 성공하는지 확인한다. 성공하면 relay 경로는 사용하지 않는다.
- 호스트 NAT가 대칭 NAT이거나 직접 경로를 막아 실패하게 한 뒤, 클라이언트 로그에서
  `릴레이 폴백`과 `실제 UE 소켓에서 ... 등록`을 확인한다.
- 서버 콘솔에서 `[릴레이] 활성` 및 방장에 전달한 host-facing 경로 수를 확인한다.

이 relay는 TURN의 최소 학습용 형태다. IPv4 UDP 전용이며, QoS/지역 분산/대역폭 과금,
DTLS·암호화 종료, 자동 공인 IP 탐지 같은 운영 기능은 제공하지 않는다.
